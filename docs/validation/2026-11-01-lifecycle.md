# 启动与收工管理验证

日期：2026-11-01。本轮补齐后台生命周期交互，不修改数据库版本。

## 行为

- 面板将“断开连接”改为“断开面板”：仍只停止观察，不停止任务。
- 新增“收工：停止实例与后台”和命令 `ZCode Pool: 收工（停止空闲实例与后台）`。通过 `poolLifecycle` 能力检测，旧后台禁用该入口。
- 收工统一调用后台 `shutdown_pool`，先阻止新派发/启动并等待已有 Worker 管理操作，再检查整个数据库中的 task lease。存在任何占用就拒绝，未停止任何 Worker。
- 空闲时逐个调用原有 Worker 安全停止逻辑，验证进程身份及原生执行状态，不使用 force。全部成功后才安排 daemon 退出；部分失败则保留后台，返回明确的部分完成错误，允许刷新检查。
- 不删除账号、任务、工作树或交付，不自动取消任务。成功响应中的 `stopping` 表示后台正在退出；不将其描述为已经验证进程消失。
- MCP 新增 `zcode_daemon_start`、`zcode_shutdown_pool`。启动后台是明确操作；overview、任务控制等其他调用不再遇到连接失败就启动后台。收工后的查询不会重新拉起进程。
- 启动保持同 pool 单次启动合并、配置切换时固定本次请求的目标，以及不重试结果不明的 RPC。仅收到明确连接失败时，显式启动工具才调用 CLI。

## 验证结果

- 根项目 typecheck 与 **185/185** 自动测试通过。覆盖所有任务占用拒绝收工、关闭期间拒绝新派发/实例启动、部分停止失败保留管理能力、查询不启动后台和明确启动的并发/目标绑定。
- 插件 typecheck、**115/115** 单元测试与 **7/7** 集成测试通过。覆盖信任和能力校验、重复请求合并、忙碌拒绝、断开与收工分离，以及回复时连接编号改变。
- **10 组** Chrome 界面联动检查通过，涵盖三种主题、五种宽度、审批与派发，未发现浏览器异常。
- VSIX 构建及白名单/校验和检查通过，包约 **600 KB**。
- VS Code **1.95.3** 隔离安装验证通过：从 VSIX 准备稳定后台；关闭 VS Code 后由 MCP 收工空池；验证 socket/lock 消失；随后 overview 返回不可用且未创建后台；显式 `zcode_daemon_start` 后再次可读取 overview。临时服务已清理。

本轮未停止用户的真实 Worker 或后台，没有消耗模型额度。真实多 Worker 收工仍需实际环境验收。测试中的图形宿主使用 Xvfb，不代表调度后台或 ZCode Server 需要 Xvfb。早先一体交付验证中的“首次查询自动启动”已由本轮的明确启动规则替代。
