# 第二轮：上下文预算、任务恢复与后台部署

日期：2026-11-01（北京时间）

[项目入口](../../README.md) · [首版真实模型实测](2026-11-01.md)

本轮由三个 GPT-6.1 Sol（max）子 agent 分别实现 MCP 输出、恢复和部署，主会话负责派发、交叉审查与统一验收。本轮没有启动真实模型任务，也未启用本机 systemd 服务或改动用户全局配置。

## 已交付

- MCP 确定性白名单视图：默认不传会话全文、原始快照、工具参数或验证命令输出；所有工具文本及错误有 16,384 UTF-8 字节硬上限。完整 ID 保留，日志和 diff 按实际返回内容推进游标。参数校验错误与原生异常同样经过输出边界。
- `resume_task` 与启动时一次恢复：核验既有 Worker、session、workspace 和原命令的原生回合后重新订阅，不发送新提示词。可恢复原任务的审批与定向取消；核验中断保留占用且不自动重跑。
- 审批控制：不把已回应审批当成未决请求；保留剩余审批数量与日志定位；等待原生订阅确认，避免 ACK 早于状态更新时误报完成；并发回复按任务串行。
- 后台服务配置：`service-generate` / `service-install`，固定绝对路径，原子写入与覆盖保护；安装命令不启动服务。支持从其他工作目录执行 `daemon-start`。
- 崩溃锁恢复：Linux abstract socket 互斥，核验旧进程死亡和 socket 身份/活性后回收；无法证明则保留现场。正常关闭在任务收尾后才释放所有权。

具体行为与限制见 [上下文策略](../context-policy.md)、[恢复指南](../recovery.md)、[服务指南](../service.md) 和 [主会话调度约定](../codex-workflow.md)。

## 验证

```bash
npm run typecheck
npm test
git diff --check
```

统一验收：类型检查通过；100 项自动测试全部通过，0 失败、0 跳过；差异格式检查通过。

测试包含真实 MCP stdio 往返与超长恶意输入、UTF-8 输出预算和 emoji 分页、原任务身份冲突、多审批与并发回复、只执行一次核验、连续重启保留核验占用，以及真实 daemon 子进程的 SIGKILL、重启与并发所有权竞争。恢复测试仅替换原生运行时边界，不调用云端模型。

本机 systemd 255 的 `systemd-analyze verify --user` 验证了默认 unit 与包含特殊字符的路径。安装测试只写临时目录。已知账号凭据扫描未发现凭据进入本轮源码、测试及维护文档。

固定测试输入下的 MCP 文本测量：单任务 wait 约 248 字节、10 个任务约 1,250 字节、短结果约 432 字节；这些是样本值而非所有任务的保证。超长中文/emoji diff 可裁到 16,384 字节且按返回游标完整拼接。

## 仍未交付或未实测

- 自动任务队列、账号续期、完整跨账号交接、自动合并和工作树清理仍未实现。
- 未安装实际 Codex MCP 配置，未打包技能或插件；已有调度流程文档。
- 新恢复机制尚未经过真实 ZCode 长任务、真实取消、自然限流或风控的全链路实测；首版双账号真实执行证据不替代这些测试。
- 不自动恢复核验中断，不提供强制解锁接口；旧格式或损坏的锁在缺少所有权证据时仍需人工检查。
- 服务配置采用 KillMode=process 保留 Worker 生命周期；不保证跨注销或系统重启存活，未配置 linger。仍仅支持 Linux 和已核验的 ZCode 3.16.3。
