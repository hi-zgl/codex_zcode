# 模型繁忙立即续跑验证

日期：2026-11-01（北京时间）

[项目入口](../../README.md) · [繁忙处理规则](../busy-recovery.md)

本轮按用户要求实现：确认当前原生回合因模型繁忙失败且没有活动执行后，在原会话立即发送“继续”，不加退避等待。默认最多三次，`busy_retry_limit` 可设为 0–10。主会话负责派发和统一验收，三个 GPT-6.1 Sol（max）agent 分别负责持久化主链、协议与精简输出、独立审查。

## 交付

- 原任务 requestId 保持幂等；每次续跑独立 commandId 和持久发送意图，次数跨重启保留。ACK 丢失或发送状态不明时只对账，不重发。
- 整个任务保持原账号、Worker、会话、provider/model 与工作区占用。只有最终成功才运行配置核验并发布结果。
- 取消意图持久化，阻止后续自动续跑；发送后的取消针对当前命令，不误停上一回合。
- 仅明确 model_busy 且归属当前回合时触发。旧 lastError、普通 429/503、额度不足、等待指令、鉴权、风控、工具错误和未知失败不作为立即续跑证据。
- 数据库 schema 升到 v2，事务内迁移并支持并发打开。旧任务缺少不可变运行绑定时不自动续跑，原有记录和结果保留。
- MCP 仅增加 retry.used/max/固定原因，继续遵守 16 KiB 文本预算，不回传模型上下文。

## 验证结果

`npm run typecheck` 通过；`npm test` 共 **136 项全部通过**，0 失败、0 跳过；`git diff --check` 通过。

覆盖：无退避立即继续与同会话/模型保持，0/2/3 次上限，未终止或活动状态拒绝续跑，错误冲突与跨回合残留，批内事件顺序，取消与 ACK 竞态，ACK 丢失恢复当前尝试，发送意图已提交但未接收时不重发，旧 schema 的租约/不可变结果/幂等迁移，以及并发迁移。

真实本地子进程测试在续跑意图持久化后执行 SIGKILL，并在 daemon 重启后观察当前续跑命令完成：没有再次 sendTurn，核验命令与最终完成事件均只有一次。独立审查还核对了取消意图跨重启和 ACK 等待时的定向停止。

## 实测边界

未发起真实云端模型任务，未修改默认 ZCode 实例。错误归属的时间依据来自本机官方 3.16.3 的 onTurnError 实现，繁忙组合由协议与假原生运行时测试构造。本轮不等于自然繁忙场景的端到端实测；无法归属的新错误形态仍保守停止，不保证自动继续一定成功。
