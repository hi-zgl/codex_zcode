# 中断、观察与取消

[开发入口](development.md) · [重试与静默](busy-recovery.md) · [运行时边界](design/worker-runtime.md)

断开 MCP 或面板不停止 daemon 与已派发任务。daemon 重启后先把未完成执行标为观察中断，再对持有占用的原任务核对并恢复观察；新的语义安排等待当前指挥。

核查使用新连接取得原 session 的初始新快照，匹配原 command/turn/session、模型绑定与目录。原命令可能仍在执行、排队或历史窗口不包含该回合时，保持未知占用。超时、502、ACK 或空的瞬时活动列表均不能作为重发或释放依据。

官方明确在接纳前拒绝的请求可使用 `admission_rejected` 停止证明：必须同时取得原命令失败账本、决策 revision 为 0，以及完整新鲜草稿中无输出、活动、队列、待处理、后台或子任务的机械证据。它不同于缺少历史回合；程序先正常保存并结束原执行，再在原总任务内建立新的受控执行，不重发旧命令。

持久发送意图之前的临时连接或会话准备故障可以安全等待、重试和让号；语义或身份错误停止，取消不发送模型命令。重启时确认没有发送意图的工作可保存并重新排队，保留已知的官方最早重试时间；存在发送意图后的未知结果仍不得重放。

## 明确操作

| 操作 | 效果 |
| --- | --- |
| 核对执行状态 / `reconcile_task` | 不发模型命令、不运行核验；更新本地事实，证实停止后可能释放占用 |
| 恢复观察 / `resume_task` | 附着原执行；符合严格条件时继续既有完成链路或安全通道恢复 |
| 请求取消 / `cancel_task` | 保存取消意图并请求停止；确认原执行停止前不释放账号 |
| 停止 Worker / `stop_worker` | 有活动或未知任务占用时拒绝 |
| 收工 / `shutdown_pool` | 全池无占用时停止 Worker 与后台，保留数据 |
| 仅停止 daemon / `daemon-stop` | 停止调度服务，Worker 可能仍运行，不是收工 |

例如在源码目录中进行明确的只读核对：

```bash
npm run cli -- reconcile_task '{"task_id":"替换为实际taskId"}'
```

恢复与对账按任务串行，不产生第二条完成链路。取消的 ACK 不是停止证明，不能强行复用未知账号。

## 核验与审批

原生成功后，尚未开始过本地核验的任务可按原策略完成核验与交付保存；保存完成前保持工作区占用。已经进入本地核验后异常中断时，不自动重复可能有副作用的命令，也不强制解锁，应核实本地进程和目录。默认 `git diff --check` 只检查差异格式，不代替功能验收。

审批只接受能归属到原任务的完整支持交互；来源未知或旧截断内容只读。答复后重新观察原生状态，不因 ACK 或审批消失推断本窗口答复被采用。面板的完整审批与不可变差异规则见[工作台合同](ui/design.md)。

鉴权、风险、额度和普通通道故障分别处理。已有实际执行证据时不盲目重放原任务；需要返工由指挥安排。连续等待和静默的默认设置见[统一恢复规则](busy-recovery.md)，真实覆盖及尚未验证情形见[当前验证](validation/current.md)。
