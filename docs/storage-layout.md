# 文件与存储布局

[项目入口](../README.md) · [运行时隔离](design/worker-runtime.md)

源码、私人账号导出与运行状态分开。普通 VSIX 使用不依赖保留开发 checkout。

| 内容 | 位置与管理 |
| --- | --- |
| 源码、脱敏测试与当前说明 | 仓库 `src/`、`test/`、`docs/`，Git 跟踪 |
| 共享账号池 | 默认 `~/.zcode_pool/`，可在面板选择执行侧绝对路径 |
| SQLite、socket、锁和日志 | `<pool>/scheduler/`，由后台统一维护 |
| 加密账号库与密钥 | `<pool>/accounts/`，仅当前用户可读；密钥与库一起备份 |
| 独立官方 Server 数据与会话 | `<pool>/workers/<worker>/`，与默认官方客户端隔离 |
| 工作目录与固定交付 | 后台创建的 worktree 与关联工件目录；含绝对路径和恢复引用，不随意搬动 |
| 原始账号导出 | 建议仓库外 `~/.local/share/zcode-pool/imports/`，目录 0700、文件 0600 |
| 扩展后台与共享连接资料 | 当前 Linux 执行侧的 VS Code 扩展 globalStorage，由扩展维护 |
| 开发截图、原始测试产物与依赖缓存 | `runtime/`、扩展 `.test-browser/` 等忽略目录；只将必要脱敏结论写入当前验证说明 |

账号导入保存在所选固定池的加密库，不随源 JSON 目录或项目改变。常用 Real F5 复用已保存连接；未配置时使用当前 Linux 用户的 `~/.zcode_pool`。

同账号跨次导入只接受严格较新的整份快照：优先比较 `usage_updated_at` 毫秒，其次 `last_used`、`created_at` 秒转毫秒；较旧、相等或缺少更新依据时保留已有记录。凭据组不变保留健康状态，变化则标为未知待查询，不混合不同代次的凭据。这些时间只是快照新旧线索，不保证凭据签发新旧；等时或无时间的新凭据也不会覆盖已有值。

`references/`、`data/accounts/`、`runtime/`、`node_modules/` 等本地资料与生成内容不纳入 Git。忽略规则不替代文件权限。文档不堆积过程日志、旧报告或归档副本。

切换面板连接目录只是选择另一个池，不迁移旧任务。已有任务、worktree 元数据、Worker 启动参数与会话可能引用绝对路径；不要简单移动仍在使用的池。当前没有完整池迁移工具。

备份应覆盖账号库与密钥、调度状态及关联交付。运行中的 SQLite 需一致性备份，不只复制 `state.db` 而遗漏 WAL。删除或移动运行数据前先确认相关任务和进程已停止；本文不授权清理用户已有池。

## 日志保留与只读统计

受管诊断日志为 `<pool>/workers/<worker>/logs/server.log`，以及 `daemon-start` 的 `<pool>/scheduler/daemon.log`；每份以 5 MiB 为轮转阈值，保留 `.1`–`.3` 三份备份。Worker 的 stdout/stderr 先脱敏再写入，单次超大写入也分片，Worker 的活动日志和备份均受该大小限制；日志 I/O 失败只报告一次静态诊断，不中断执行。

daemon 继承 append 文件描述符，每 5 秒检查并在原 inode 上复制、截断，因此是软限额：检查间可超过阈值，复制与截断的短窗口可能丢失并发诊断写入。任务事实仍保存在 SQLite。前台与 systemd 的 daemon 输出由调用方或 journal 保留；官方运行时内部日志不在上述轮转范围。

`npm run cli -- storage-status` 无需启动 daemon，按受管日志、交付、Worker 数据、调度状态、账号、工作目录等组输出保留策略与普通文件的逻辑字节数。它只遍历元数据，不跟随符号链接，不读取池内文件内容，也不创建、迁移或删除任何池数据。统计不是原子快照或物理磁盘占用，硬链接按路径计数；输出同时报告跳过、不可读或变化的条目。

保存交付与文件快照、Worker 会话与运行时数据、SQLite/WAL 与任务历史、账号库与密钥均继续保留，没有新增自动删除或全局容量上限。既有终态工作目录清理仍需确认成果安全、无占用且无活动 Work 的执行或验收引用；`storage-status` 不触发清理。
