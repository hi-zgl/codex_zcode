# 用户流程与状态规格

本文保留实现前的设计基线（`21d4663`）。下文阶段、拟议文件与接口用于说明设计约束，不代表当前开发状态；已落地代码、运行方法及验证边界以[运行与测试指南](implementation.md)和[验收记录](../validation/2026-11-01-vscode.md)为准。

## 共用状态与按钮规则

屏幕同时显示四层信息，不能互相替代：

| 维度 | 示例 | 呈现规则 |
| --- | --- | --- |
| 连接 | 未连接、连接中、已连接、重连中、连接中断、不受支持 | 属于本客户端，不改任务状态；显示主机/pool 和最后成功同步时间 |
| 后台任务 | `running / verifying / succeeded` 等 | 保留 daemon 原值及中文标签；缺字段显示“—”，不凭无事件推断完成 |
| 资源占用 | 已占用、已确认停止但仍在核验、占用未知、可复用 | `leaseHeld` 与 `executionStopped` 分别解释；证明不足时不可复用 |
| 本地审阅 | 待人工审阅、本客户端已审阅 | 不写回 TaskStatus，不替代核验，不表示 Codex 或其他窗口已审阅 |

任何写动作都要求已连接、可信上下文、对应 capability、明确目标身份及有效详情；离线快照只读。提交时只锁住目标动作，保留阅读和导航，不冻结整个面板。按钮不可用时在附近说明原因，不能只靠 hover；在不适用的对象上隐藏动作，在用户期待但前置条件不满足时保留禁用动作。

动作反馈依次为“提交中 → daemon 受理/等待原生确认 → 已观察结果”。只有最后一步能呈现完成。网络超时、响应丢失或安全投影失败统一呈现“结果待确认”，保留目标 ID 与跟踪入口，不自动重试写动作。普通操作无二次确认，最终按钮本身应写清对象和效果。

## 首次打开、连接与多项目

首次屏幕：

```text
ZCode Pool                         未连接
执行侧：SSH: host-a（Linux）
pool：/home/me/.zcode_pool
[连接已有 daemon]  [修改设置]  [运行指引]
连接后读取此执行侧的任务；这里的路径属于 host-a。
```

| 场景 / 触发 | 屏幕与可用操作 | 结束条件 / 失败后保留 |
| --- | --- | --- |
| 首次打开或 F5 调试 | 原生 Welcome 和工作台连接页；预填 Host 环境、用户设置的 pool 或该 Host 默认值；点击“连接已有 daemon”才发起连接 | 完成能力协商和安全概览后进入列表；本轮没有真实 F5 配置 |
| 配置主机与 pool | Host 来自当前 VS Code 本机/SSH/WSL authority，只读展示；pool 用执行侧绝对路径设置，显示解析结果；“保存”不隐式连接 | 换主机走 VS Code Remote 窗口；不在 Webview 做任意 SSH/HTTP 连接器 |
| 无 daemon / socket 不可达 | “无法连接此 pool”，显示固定诊断类别、Host、pool、重试和运行指引 | 重试只连接；不自动安装依赖、清锁、启动 daemon 或改服务；不伪装成“暂无任务” |
| 不支持环境 | 说明原生 Linux、SSH 到 Linux、WSL 支持边界；Windows/macOS 纯本机、browser-only 禁用连接 | 提供远程运行指引；Dev Container/Codespaces 标为待验证，不承诺已经支持 |
| 连接但无账号 | 任务页仍可查看已有/历史任务；资源账号组“此池尚无账号”；M2 提供“从执行侧文件导入”，M1 提供 CLI 指引 | 不弹登录页，不自动创建 Worker；成功导入后留在账号列表 |
| 有账号但无 Worker/workspace/任务 | 各组独立空态：“启动 Worker”“创建任务 workspace”“新任务”仅在能力具备时可用 | 不把四种空态混成导入向导；历史任务不因资源缺失隐藏 |
| 多根 VS Code 工作区 | 项目选择列出已识别源仓库及必要父路径，默认活动文件所属仓库；无法唯一确定则要求选仓库 | 选项目只改筛选；“整个池”可看其他项目，不迁移资源 |
| 未打开仓库 | 可以连接并浏览整个池；新建 workspace 前用 Host 原生目录选择器明确源仓库 | 没有仓库时不随意以当前目录派发 |
| 同池多窗口 / CLI / MCP | 显示连接身份、task ID、revision；当前没有创建客户端来源字段，不伪造“由谁创建”；UI 预检查资源后仍由 daemon 原子裁定 | 别客户端抢先占用时展示占用任务链接和刷新；不强行覆盖 |

切换 pool 时先停止本窗口旧连接的 wait/刷新，清除待提交动作和审批读取令牌，再进入新 pool 的连接页。旧 pool 任务不受影响。筛选、选中 ID、页签按 authority + pool/store 身份隔离；不能把旧 pool 的 task ID、额度或审批卡片带到新连接。

主动“断开”只断开客户端，不发 `daemon_stop / stop_worker / cancel_task`，随后不自动重连。意外断连可在本次用户建立的连接范围内有界重连；暂停/重试入口始终可见。重连先协商并取新快照，不能只把旧连接灯改绿。

连接中断时保留旧列表及“缓存 · 最后同步于…”；所有写动作禁用。任务仍显示“上次已知：执行中”，不一概改成 `interrupted`；只有 daemon 报告的任务中断才使用该状态。窗口重载不恢复尚未发出的动作；若动作可能已发送，先按其身份查询结果，不重放。

## 任务列表、筛选与详情

任务屏幕：

```text
SSH: host-a · pool-A   [项目：repo-a ▼]   最近50条 · 同步16:44
[状态：全部 ▼] [Worker：全部 ▼] [搜索已载入任务] [刷新] [新任务]
任务ID / 项目与workspace / 状态 / Worker / 更新时间或— / 续跑
[列表，选择不触发执行]           | [选中任务详情及四个页签]
范围：当前筛选12 / 已载入50；历史总数未知
```

默认当前项目、全部状态。M1 将 `overview` 的最近创建 50 条反向展示为“最近创建优先”；当前 compact task 没有更新时间/标题，不伪称按更新时间排序，不截取 prompt。M2 有字段才显示安全摘要及“最近更新”，稳定排序需以 ID 兜底。没有当前项目的近期记录时说“最近 50 条中无此项目任务”，提供“整个池”和清除筛选，不能说该项目没有历史。

状态筛选包括全部、需要处理、执行中、最近结束及底层状态；Worker、任务 workspace 和文本筛选只作用于当前已载入集合。文本可查 ID、已提供的安全摘要、仓库/workspace/Worker 标识，不检索未加载日志或 prompt。“需要处理”包含待审批、阻塞、失败、中断/未知占用和具备交付的待人工审阅；`verifying` 属于执行中，不表示需人工处理。若失败同时仍执行不明，优先展示占用警示；分组中一行只出现一次。

计数同时标明范围与来源：“筛选 12 / 已载入 50”，不把本页数量称为全池总数。资源组是 pool 级，不能用任务页项目筛选后的部分任务断言 Worker 空闲。M1 最近窗口之外若有已知 task ID，可明确打开该 ID 的详情；不提供看似可用的“下一页历史”或完整历史搜索。

M3 `ui_list_tasks` 才提供稳定游标分页、服务器筛选和总数/计数范围。筛选变化重置游标，保留可返回的选中详情；加载更多保留滚动，按 task ID 去重。收到 `CURSOR_INVALID / CURSOR_STALE` 保留当前可读行，说明快照失效并提供“重新加载列表”，不静默拼接不同快照。其他客户端有新任务时显示“有更新”，应用更新不偷焦点或跳走正在审阅的任务。

详情顶部固定短/完整 ID、后台状态、连接新鲜度、占用提示及按上下文选择的主动作；元数据展示项目、实际 worktree、分支、Worker/账号、session、模型、续跑 used/max。字段缺失显示“当前接口未提供”；M1缺retry时不伪造0/3。M1概况读 `get_result`，M2以 `ui_get_task_detail` 读安全详情并另读不可变result；结果为空显示“交付尚未生成”，不显示 0 文件/0 测试成功。四个页签分别为：

| 页签 | 内容 / 按需加载 |
| --- | --- |
| 概况 | 状态、失败/阻塞类别、绑定、资源、核验策略和恢复建议；不默认读完整 prompt 或原生会话 |
| 审批 | pending 列表、完整度、归属、操作参数和单项答复；只有有审批才强调提醒 |
| 交付与核验 | summary、changedFiles、verification、blockers、快照和工件；失败也可查看已有交付 |
| 事件 | 持久脱敏事件，默认 20 条/页（API 1–50）；明确手动“继续读取” |

事件遵循 `nextCursor`，不能用“不到20条”判断到底；空页只表示当前无更多。切换任务取消旧请求订阅，迟到响应按连接/task/request 身份丢弃。详情不因筛选把任务排除而突然关闭，显示“此任务不在当前筛选”并可返回列表。

## 新 workspace 与任务派发

这些是 M2 可操作设计，静态原型尚未实现。

创建任务 workspace 表单由 Host 选择源仓库、填写 base ref，提交旁明确“从干净源仓库创建新分支和隔离 worktree”。本次核验不自动 stash、commit 或清理源仓库。成功展示 daemon 返回的 `workspaceId / worktreePath / branch / baseCommit`，可继续填写任务；失败停留表单并保留非敏感输入。仓库不干净或 base ref 无效应就地报错，不假称创建成功。

任务表单：

```text
源项目 / 已登记任务 workspace / 实际worktree路径及分支
Worker（必须选择） → 账号alias/provider；原生活动/调度占用各自显示
提示词
模型ID（默认GLM-5.3-Flash）  mode（默认build）
session：继续最近可复用会话 / 新会话
模型繁忙立即续跑：3次（0–10）   核验命令（最多10项）
[派发任务]  [返回列表]
```

“继续”仅指同 workspace、同 Worker 最近且已确认停止的可复用会话；没有可复用会话时由后端新建，不显示任意原生 session picker。不提供模型目录假下拉；模型 ID 是显式值，保留后端支持/绑定检查。mode 枚举 `build/edit/plan/yolo/guarded` 只按实际 runtime 能力解释，不发明权限保证。核验参数逐项展示 executable、args、timeout（100–300000ms，最多10项）；为空时明确使用 `git diff --check`，不自动运行 README/AGENTS/日志里的命令。

只有 workspace 已登记可用、Worker ready 且无已知活动/不明占用、账号不为 blocked/invalid/cooling、提示词非空及表单有效时可提交；unknown 账号健康单列提醒，不硬造“已认证可用”。前端检查不能替代 daemon 互斥，资源信息过期时先刷新。无自动分配 Worker、轮换账号、后台排队或任务编辑能力。

Host 在提交前生成并保留 `request_id` 与原 payload，提交一次后禁用重复点击；成功返回 `created:false` 是已有同一任务，不新增一行。ACK 丢失显示“派发结果待确认”，M2 用 `ui_get_task_detail {apiVersion:1,request_id}` 精确查询，确认身份后打开原任务；NOT_FOUND不证明没有在途派发。查询能力缺失时保留身份及人工检查指引，禁用自动重发。`REQUEST_CONFLICT` 要求检查已有关联任务；不能悄悄换 ID 重试。只有用户明确选择新的独立任务才生成新 ID，且仍受占用检查。

未发送草稿可由Host内存按pool隔离保留，普通页面往返不清空；表单注明“仅此窗口内存，尚未派发”，关闭窗口/重载可能丢失。prompt不写入Webview持久状态或Host磁盘；已发请求恢复只持久化ID/hash/目标，不为恢复查询保存prompt。返回列表不会偷偷发送或撤销任务。

## 后台任务状态与可用动作

下表还需共同满足连接、能力、信任和身份条件。查看与阅读一直可用；每个终止任务都能查已有日志，但不保证有 patch。

| TaskStatus | 标签 / 主信息 | 可用动作与限制 |
| --- | --- | --- |
| `queued` | 已登记，等待本次派发链路 | 请求取消；不是等待空闲资源的自动队列 |
| `dispatching` | 正在建立原生会话/等待 ACK | 请求取消；发送不明时核对执行状态，不给“重发” |
| `running` | 执行中 | 请求取消；审批按当前 pending 独立出现 |
| `waiting_approval` | 等待审批 | 审阅当前单项；答复受下一节完整度/原生状态门槛 |
| `verifying` | 核验中 / 正在保存交付 | 查看命令和进度；不提供停止核验、重复核验或“待人工审阅”按钮 |
| `succeeded` | 已完成 · 待人工审阅/本客户端已审阅 | 查看交付与核验；具备清单和哈希时可标记本地审阅 |
| `failed` | 失败，显示原生失败或核验失败 | 查看已有交付/诊断；无通用“重试原任务”按钮 |
| `cancelled` | 已取消（已证明原执行停止或从未派发） | 查看历史；不把取消 ACK 直接当成此状态 |
| `blocked` | 已阻塞，显示安全类别 | 核对状态、恢复观察、请求取消；不能接受审批绕过账号阻塞 |
| `interrupted` | 观察/发送/完成链路中断 | 核对执行状态、恢复观察、请求取消；核验曾中断时恢复受拒绝并保留检查指引 |

`leaseHeld:true` 而执行无法证实时叠加“占用未知”，同时列出 Worker、workspace 和持有任务；最终状态字样不能覆盖该警示。`runningTaskCount:0`、一个结果对象或离线快照不能单独证明可复用。M1 缺 `executionStopped` 等字段时写“接口未提供停止证明”，不自行补成 false/true。

## 繁忙、取消与恢复

模型繁忙卡片展示“原会话立即继续 · 已使用 1/3 次”；used 是持久化的续跑发送意图数，首次原任务不计入，0 关闭，最大10。没有退避等待、倒计时或“稍后自动换账号”。只有 daemon 证明本次模型繁忙失败、精确归属、原回合已终止、无活动执行且绑定相同时才发送固定“继续”；普通429/503、限流、额度不足、工具/正文文字、未知发送均不触发。上限耗尽显示失败和已用次数，不提供重置计数绕过上限。[繁忙规则](../busy-recovery.md)

| 操作 / 返回 | 用户反馈及后续动作 |
| --- | --- |
| 请求取消任务 | 立即显示“取消请求提交中”，不移除行；持久化后“已记录取消请求，等待停止确认”，阻止后续自动续跑 |
| `terminationConfirmed:false` / 尚无 turn 身份 | 显示“仍保留占用”；取消按钮锁为“等待确认”，可继续阅读、刷新或核对状态；不能改成空闲 |
| 取消时响应丢失/断线 | “取消结果待确认”；重连先读取持久取消意图与原任务，不补发新任务，不停止整个 Worker |
| 核对执行状态：`reconcile_task` | 不发送模型命令、不运行核验；**可能更新本地任务记录并在证实停止后释放占用**。提交旁说明此效果，不叫纯刷新 |
| 对账发现原执行仍活动 | “已定位原执行，可恢复观察”；对账自身不附着、不续跑；显示恢复入口 |
| 对账发现原生终止 | 显示已证实停止及“本次未运行配置核验”；根据后端实际 lease 显示释放与否，不宣称已成功交付 |
| 恢复观察：`resume_task` | 行旁说明“附着原执行；若已结束可能完成核验，明确繁忙时可使用剩余续跑”；调用本身就是显式操作，不包装为刷新 |
| `attached:true` / `finalizing:true` | 分别显示“已恢复观察”/“正在完成核验与交付”，继续跟踪实际状态 |
| `requiresInspection:true` / 原回合不能唯一归属 | 显示固定原因、保留占用、Worker/workspace 检查入口；无强制解锁或猜测重发 |
| 曾进入的本地核验被中断 | 明确“可能遗留本地子进程，需检查”；不自动重跑核验或释放占用 |
| `operationInProgress / alreadyStopped` | 展示后台已有操作或已停止的事实，禁重复提交，刷新实际结果 |

取消整个任务与“取消本次原生交互”分开命名。核验中当前没有停止本地核验的 API，因此不能把“取消任务”画成能终止核验的按钮。普通成功、失败和取消最终结果之后，“恢复观察”不等于重新开始；用户如需新任务必须走新的显式派发。

## 单项审批的完整生命周期

审批屏幕：

```text
任务 / attempt / approvalID    待处理 / 等待原生确认
操作类型 · 目标路径 · cwd · 请求范围 · 归属
完整度：摘要预览 / 加载完整内容 / 完整 / 无法补齐
[脱敏参数，按字段分页；显示缺失/截断项、已读量及内容hash]
[拒绝本次操作] [只批准本次操作]
后台状态与其他pending项；[取消整个任务]在独立任务菜单
```

UI 使用 `ui_list_approvals / ui_get_approval / ui_read_approval / ui_respond_approval`，不回退旧 `respond_approval` 绕过内容绑定。多个审批逐项列出，不做批量批准；预览前20项或数量被截断时明确总量/还有未加载项，不能显示“已全部审阅”。旧持久日志约4000字符截断后，重复读取不能恢复丢失内容；MCP `reviewComplete:true` 也不能替代 UI 的完整来源和绑定契约。

| 审批状态 | 按钮与反馈 |
| --- | --- |
| 只有摘要 / 旧 daemon 无完整来源 / 原生归属不明 | 整个审批只读，包括批准、拒绝和交互取消；可看日志/本机原生处理指引，任务取消独立按安全归属处理 |
| 有完整来源但尚有未读页 | “只批准本次”禁用并说明缺项；拒绝仅在最新归属、原生允许选项和绑定契约都满足时可用，不要求读完全部内容；来源截断/未知schema则整卡只读 |
| 完整内容已加载且完整度可信 | 明确目标、参数、cwd、范围；accept 还要求账号可用、无取消意图、原生pending未变且已有相应授权。滚到底或勾选“已阅读”不自动授予权限 |
| 原生只支持其他 option / freeText | 显示“不支持此交互的答复形式”，整体只读；不伪造任意表单或 accept 映射 |
| 提交答复 | Host固定action_id，只提交一个decision，携带task/attempt/approval、review_id及内容hash/revision；同卡所有答复按钮立即禁用 |
| RPC ACK accepted / APPROVAL_RESPONSE_PENDING | 保留卡片“答复已发送，等待原生确认”；原 TaskStatus 可仍 waiting_approval，不立即加已批准成功徽章 |
| 原生状态有可关联本次答复的确认依据 | 才可标“原生已确认本次答复”；其他审批仍待处理时保留 waiting_approval，只有实际任务更新才切 running |
| 新 revision 仅证明该项从pending消失 | “此审批已不再待处理，无法确认采用了哪次答复”；可能由其他客户端处理、取消或失效，不凭消失虚报本窗口批准成功 |
| 其他客户端抢先处理 / APPROVAL_GONE | 有明确来源证据才说“已由其他客户端处理”，否则说“已不再待处理或已失效”；刷新pending，不重发本窗口决定 |
| APPROVAL_CHANGED | 清空本次读取进度/可提交令牌，显示变化并重新加载完整内容；旧hash不可提交 |
| APPROVAL_READ_ONLY / 不支持原生决定 | 就地解释只读原因，仍保留阅读/原生处理入口；不能从菜单或命令面板绕过 |
| ACK 丢失 / 网络断开 | “答复结果待确认”，锁住重复/相反决定；恢复后查原action receipt及新鲜pending/revision，不重放intent、不换action ID绕过 |
| blocked/invalid/cooling 或取消意图已记录 | accept 禁用；其余决定仍需新鲜归属/能力检查，不用批准解锁账号 |

按钮按经过验证的原生决定语义呈现，不固定显示三个。`accept` 是只批准当前操作；`decline` 是拒绝该项，原任务可由Worker调整后续行动，不等于任务失败或停止。当前permission将accept映射allowOnce、decline/cancel都映射deny，因此只显示“只批准本次”和“拒绝本次”，不制造一个有独立停止效果的“取消交互”按钮；只有已验证支持独立cancel语义的类型才显示该项，也不保证停止整个任务。workspaceHookReview不支持通用答复，保持只读。文案不承诺“以后都允许”或永久权限修改；提交决定本身不再弹确认框。

## 账号、额度、导入与 Worker

账号详情上半部显示 alias、provider、plan、健康；下半部分别列额度的值、单位/分母、来源、观测时间、官方生成时间、重置时间及新鲜度。默认不显示邮箱、token、源文件路径。健康与额度分开：available 不保证余额充足，unknown 不等于无额度，cooling 不编造恢复倒计时。

| 数据情形 | 呈现 / 可用操作 |
| --- | --- |
| 导入时 quota | 标“导入快照”；原 `usage_updated_at` 单位不明时不换算日期；没有可信观测时写“更新时间未知” |
| 从未读取 | “未查询”，不用0或空进度条；有 ready Worker 和 capability 才可“查询当前额度” |
| 主动 `probe_worker` / `ui_probe_quota` | 明示会连接官方服务读取认证/额度、不发模型回合，但可能将账号health从unknown升available；只对目标Worker显示进行中，不随普通刷新或打开页面自动查询 |
| 查询成功 | 区分官方generatedAt/serverTime与Host接收时间；当前probe不会更新账号旧quota缓存，新响应不能伪装成旧快照已变实时 |
| 查询失败 / 过期 | 保留上一次值并分别标失败、最后成功时间/过期；M2 live按可靠observedAt默认120秒提示陈旧，仅是UI提示、非余额保证；时间未知/倒退显示“新鲜度未知”，导入快照observedAt为null |
| 明确额度0 | 显示0及来源时间；不是“未查询”或错误；无有效分母不画百分比，不把不同provider单位相加 |
| 旧数据/健康未知 | 不依赖旧额度条自动派发或宣称可用；用户可显式探测，真正拒绝由daemon负责 |

导入使用 **Host 原生文件选择器**，选当前执行侧的1–100个OAuth JSON文件；Webview只发“请求导入”意图并接收匿名摘要，不接收文件URI、凭据文本或临时上传内容。SSH/WSL必须明确“在host-a/该发行版选择文件”，本地文件不能直接当远端路径传入；首版不做凭据跨主机拷贝。取消文件选择无toast成功、不改变账号。

文件选择前说明同alias可能覆盖池内凭据记录；不虚构导入预览/回滚API。导入成功显示文件数、记录数、同批去重数和返回的匿名账号；duplicateCount只是所选文件中按alias去重的数量，不是池内已有数或新增数。同批按导出时间选择记录，不承诺与库内已有导出代次比较后才替换。当前不提供改名、登录、删除、导出或加密.zsb解包。错误只定位文件序号/记录序号和固定原因，不回显文件名、token、原始JSON；不宣称批量事务回滚，写入结果不明时先刷新实际列表。

Worker 行同时显示 native `runningTaskCount` 与 daemon lease/未知占用。ready、stopped、unreachable、identity-mismatch、unsupported 均用实际文案；ready绝不显示“必定空闲”。

- 启动：选明确worker ID与account alias；同账号有其他未停止Worker、启动进行中或已知占用时禁用/由daemon拒绝；不热切换账号，不停止共享官方实例。
- 探测：已有ready Worker才可用；只查询认证和额度，成功只按实际响应更新显示，不保证健康状态自动全修复。
- 停止：只对归属确认、没有活动/未知调度占用且后端允许的Worker开放；提交后显示“正在停止”，重新读取到stopped才成功。其他客户端已占用则显示关联任务，不提供强停。
- workspace资源：展示源仓库、实际路径、分支、baseCommit、activeTaskId；只有创建和查看能力，不画出没有公开API的合并、清理、放弃按钮。

## 交付、累计 Diff 与本地审阅

交付屏幕：

```text
任务T / 已完成 / 核验范围           [本客户端标记已审阅]
总结、blockers
核验：命令 / 退出码 / 截断摘要 / 尚需功能验收
快照manifest hash · baseCommit → 交付快照（相对base累计）
文件列表（tracked / untracked / 二进制 / 不可用）
[原生Diff] [patch文字] [打开当前文件：当前磁盘] [工件内容]
```

先加载结果和验证事实，再按需加载差异。不配置核验命令时后台默认 `git diff --check`；即使退出码0也只说明该检查通过，醒目标明“仍需功能验收”。exitCode null是未知/被中断，不是0；输出摘要截断要有标签，不编造完整测试报告。原生失败可能只有blocker而无patch，不能据此显示“没有修改”。

当前 `get_diff` 读取不可变patch文字，默认4000、最多8000个 **UTF-16 code units**，offset不是字节/行号；使用nextOffset继续，未读完显示“部分patch”，不能当完整Diff审阅。`available:false` 表示此任务尚无可读patch，不等于空变更。二进制patch按类型展示可读元信息，不以乱码假装文本。

现有patch是 `git diff baseCommit --`，包含该任务workspace从base开始累计的tracked变更，可包含先前任务；不能命名“仅此次任务新增改动”。M2文件Diff只有不可变base/final内容及manifest可用时调用原生 `vscode.diff`；旧任务缺对应快照时禁用并解释，不从当前工作目录推造历史内容。主机、task、manifest和文件身份由Host检查，Webview不能传任意路径。

未跟踪文件可能在changedFiles中且已有内容工件，却不在git patch里；列表标明“未跟踪工件，未包含在patch”。原生get_result的元数据还不足以安全还原原路径，M1只展示可证实信息，内容入口注明缺受限读取能力。M2通过manifest/fileID读工件，区分文本、二进制、符号链接目标；不跟随符号链接读取任意文件。打开当前文件必须标“当前磁盘版本”，同历史Diff分开。

“标记本客户端已审阅”只在交付清单/哈希已知、显示范围完整、用户已查看总结/核验与所需变更后可用，不自动批准/合并。Host workspaceState仅保存 `(remote authority, pool/store identity, taskId, manifest sha256)` 对应标记；hash变化标记失效，不存内容。M1没有manifest因此禁用，静态原型演示标记不代表后台已有API。可撤销本地标记；它不改succeeded、不解锁资源、不向Codex发消息、不宣称跨窗口共享审核。

## 键盘、窄屏与反馈

生产验收使用VS Code深色、浅色及高对比度主题；颜色只强化含义。状态图标需有文本和accessible name，屏幕阅读器读出完整taskID、状态和按钮禁用原因；减少动画时关闭装饰动画，连接进度仍有文字。

原生Tree使用VS Code默认方向键、Enter和上下文菜单。Webview Tab顺序为上下文/筛选→列表→详情页签→内容→动作；按钮Enter/Space触发，页签左右/Home/End切换且有aria-selected，读代码可水平滚动但不截获编辑器全局快捷键。无默认全局快捷键冲突；列出的顶层操作可经zcodePool命令完成相同目标校验，审批决定/本地审阅也能在面板用键盘提交。

宽屏双列，小于760px单列“列表→详情”；小于480px表单/元数据堆叠，可用审批决定换行但标签不省略；280/320px及200%缩放时关键按钮仍可达，代码可独立滚动。返回恢复列表选中/滚动，筛选不偷焦点；用户打开详情时焦点到详情标题，关闭原生选择器或对话框回原触发点。只有必要模态框才圈住焦点；Escape关闭模态/返回当前列表，不取消任务、不自动拒绝审批。

| 反馈类型 | 呈现 |
| --- | --- |
| 输入无效 | 字段旁固定文字，提交聚焦首个错误，保留输入；不靠toast解释 |
| 普通查看/刷新成功 | 更新就地时间与轻量live region，不发系统通知 |
| 资源冲突/不支持/缺能力 | 当前动作旁说明原因及可用检查入口；稳定错误码映射，不解析原生异常文本 |
| 动作待确认 | 持续卡片展示目标、阶段和可跟踪操作；toast只能补充，不能是唯一状态 |
| 新审批/关键失败 | 可按用户偏好发一次可导航通知，按task+revision去重；不包含prompt/审批全文/凭据 |
| 复制诊断 | 仅Host/pool身份、连接状态、方法、脱敏错误类别、task/requestID和revision；内容预览可检查，不默认附原生日志/路径/邮箱/token |

M2设置只包含Host侧User/Remote Settings的machine-scope `zcodePool.poolHome`，以及窗口级 `zcodePool.overviewIntervalSeconds`（默认30秒，15–300秒）；Host环境只读，诊断为受限复制动作。pool保存后回未连接页，不接受仓库覆盖或Webview路径。刷新间隔只影响可见视图发现任务，不触发probe或模型操作；缓存/重连遵循架构的固定生命周期策略。修改UI设置不改已有任务的繁忙上限、核验命令或账号，也不提供Node/loader或daemon启动设置。[扩展架构](extension-architecture.md)
