# 主会话调度约定

Codex 主会话负责拆分任务、派发、判断阻塞与验收；ZCode Worker 保留具体实施所需的会话上下文。VS Code 面板用于任务监控、额度检查、必要审批与人工干预。主会话不接收或逐条复述 Worker 的完整对话、工具调用和命令输出。

## 首次连接

安装版 VSIX 已包含调度后台、CLI 与 MCP，执行侧仍需 Node.js 24+ 和官方 ZCode 运行环境。打开工作台确认 Linux 执行侧和连接目录，按需启动后台，并在“额度与资源”准备账号、执行器和任务目录。点击“连接 Codex / 生成 MCP 配置”，将生成的配置一次添加到同一执行侧的 Codex 后重新连接 Codex。生成配置不自动修改 Codex 配置，也不证明连接已建立；以 Codex 能调用 `zcode_overview` 并看到同一池的资源为准。普通用户无需从仓库运行 npm 命令。

MCP 与面板使用同一执行侧的共享连接资料。面板修改目录后，后续 MCP 工具调用读取新目录，无需重复添加 Codex 服务器配置；旧目录中的任务仍保留，不会迁移。面板断开、关闭 VS Code 或关闭 MCP 入口不代表任务停止。后台连接与 Codex MCP 连接是分别建立的。升级扩展不自动重启旧 daemon，已有服务仍按其实际能力提供功能。

日常把目标、约束和验收方式交给 Codex。面板的“高级操作”保留手动派发入口；无需逐个填写表单来让 Codex 调度。

## 派发

1. 使用 `zcode_overview` 查看实例、任务与池级并发状态，必要时调用 `zcode_probe_worker` 检查目标实例；额度在线查询按需发起。
2. 为互不干扰的子任务创建独立 workspace。给 Worker 的任务说明包括目标、可修改范围、验收命令和需要交付的结果；只传递与该子任务有关的背景。
3. 使用 `zcode_dispatch_task` 明确指定 Worker 与 workspace，并保存返回的 taskId。每个新任务使用新的 request_id；同一请求重试复用原 request_id 和相同参数。
4. 同一 workspace 或 Worker 被未知执行状态占用时，先恢复或对账；不能通过创建重复任务绕开占用。

## 并发与人工干预

后台的池级并发上限对 MCP 和面板同时生效。用户可在面板“设置 → 并发任务”调整，Codex 可通过 `zcode_get_pool_policy` 查看，并在已有授权范围内使用 `zcode_set_pool_policy` 修改。范围为 `0–64`，`null` 不限制；`0` 暂停新派发，已有任务继续。降低上限不取消正在运行的任务。

槽位包含审批等待、核验及执行状态未确认但仍持有占用的任务。达到上限时新派发直接拒绝，不自动排队；等待槽位释放后再决定是否派发。不要因为超限而创建重复任务、切换账号绕过约束，或自动提高用户设置的上限。

## 等待与上下文预算

- 用一次 `zcode_wait` 等待多个 taskId，携带已有的 revision，避免反复读取未变化的状态。
- 模型繁忙的有界自动“继续”由 daemon 管理；主会话只读取 `retry.used/max`。不要在它续跑时另派发相同任务；需要停下时调用 `zcode_cancel_task`。
- 运行期间以状态变化为依据，不循环拉取 `zcode_get_logs`，不把每条工具事件转述给主会话。
- 完成后读取一次 `zcode_get_result`。按需检查 `zcode_get_diff`；日志只用于定位具体失败或审批原因。
- 分页时使用工具返回的 nextCursor / nextOffset，不自行猜测下一页位置。被省略或截断的内容不视为已审查。
- 默认输出不包含完整会话。详细输出保存在本地；MCP 的具体预算与截断规则见 [上下文输出策略](context-policy.md)。

## 审批、恢复与验收

- 仅在实际运行环境提出审批时处理，依据实际操作内容和已有授权决定。摘要不足以判断时，按提示读取相关片段或检查本地内容；不能因为有 approvalId 就直接批准。面板保留完整来源、归属与版本校验，不默认使用 `yolo` 或自动批准。
- daemon 重启或连接中断后，先检查当前任务状态，再使用 `zcode_resume_task` 恢复原回合管理，或用 `zcode_reconcile_task` 做只读对账。不重新发送原提示词来“恢复”。具体边界见 [任务恢复](recovery.md)。
- 核验失败的任务保留工作区。需要返工时，在确认原任务停止后继续原会话，明确派发修正目标。
- ZCode 自述完成、回合终止、测试通过和集成成功是不同的证据。审查实际差异与验证结果后，再集成到目标分支并检查集成结果。
- 当前没有自动合并或清理工具；集成由调用方执行。不要在未审查或仍有执行活动时删除工作树。

## 向用户汇报

只汇报已完成的交付、核验证据、剩余阻塞与需要用户决定的事项。不要把所有 Worker 的思考、日志、重复状态或完整会话堆入主会话。
