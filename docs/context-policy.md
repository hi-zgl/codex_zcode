# 上下文预算与按需查看

[指挥约定](codex-workflow.md) · [交互设计](design/agent-interaction.md)

MCP 是精简控制入口。程序以确定性代码投影状态和结果，不调用额外模型做摘要。完整会话、工具事件和文件内容留在本地；面板读取不会自动进入指挥上下文。

## 日常返回

交办和推进返回总任务、当前 revision、必要控制标识、阶段/执行/验收摘要、固定交付与待办。等待只关注关键变化；无变化超时只返回游标，不重复展开整个工作。普通恢复错误不逐次唤醒指挥。

详细结果、日志和差异通过 `zcode_inspect` 按需读取。池状态和明确资源动作由 `zcode_pool_control` 提供。日常工具只公开这五类入口，高级 CLI 和 UI 方法不会自动变成 MCP 工具。

## 预算与准确性

每次工具调用一个文本块，最终 JSON 文本最多 16,384 UTF-8 字节，含转义、错误与提示。上限不是默认输出量，也不是 token 估计。控制标识不可截成另一个可操作值，超过预算明确失败；写操作可能已经完成时，应查询原记录，不能自动重发。

MCP 使用白名单字段；新增后台属性不会自动透传。prompt、凭据、原生 raw snapshot、完整历史和任意 native payload 不作为对象返回。人类可读摘要还会掩码常见令牌格式，但任意自然语言秘密无法保证全自动识别，原始资料仍按本地私有数据保护。

日志使用持久 revision 分页，只返回完整事件，游标推进到实际返回的最后一条；空页保持原游标。差异的 cursor/offset 沿用 JavaScript UTF-16 字符位置，不是 UTF-8 字节。直接使用返回的下一位置，不自行换算或跳过截断内容。

## 审批与续接

短审批预览不是完整授权依据。需要时按引用读取完整支持的操作与参数，再按已有授权决定；缺失、截断、未知类型或脱敏影响判断时只读或本地复核。UI 的完整来源、分片与指纹规则见[工作台合同](ui/design.md)。

续接保留目标、完成标准、阶段、交付引用、有效结论、未决事项和下一步，不把完整实施对话复制给新账号或新指挥。资源和状态由程序维护，指挥只补充必要的安排与语义判断。
